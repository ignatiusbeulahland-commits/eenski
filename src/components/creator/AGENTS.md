- Product create screens use the guided `products/Create.tsx` with primitives in `CreateKit.tsx`, per-type sections in `CreateDetails.tsx` and preview in `CreatePreview.tsx`; copy, validation and mapping into the existing type configs live in `src/lib/creator/createGuide.ts`. Create shows one step per page (step 1 at the create URL, steps 2–5 at `?step=n`, parsed by `parseCreateStep`); Next and the step rail never block; Save draft always works (`draftAnswers` fills safe defaults), only Publish checks every step and returns to the earliest unfinished one, and a direct link to a later step with no answers resets to step 1. Create only fills product config fields (course skill/level/presentation and each other type's category subtype live in that type's config schema with zod defaults; dropdown lists in `src/lib/creator/courseMeta.ts`, every category dropdown offers Other); editing keeps the standard editor. Why: type-specific onboarding without changing the product schema or Manage Products.
- Landing pages store template, cover and up to four image sections with zod defaults so older saved pages still load; images go through `creator/ImageUpload.tsx` (resized). Why: storage compatibility and small local data.
- Storefront banners are one saved image whatever the source (upload, or drawn on a canvas from tidied words by `src/lib/creator/banner.ts`) with zod defaults; the storefront photo picker writes the shared Creator profile photo. Why: one banner field for every source, older stores still load, and the photo stays consistent with Manage Profile.
- Course presentation files and Media Library uploads keep their bytes in IndexedDB via `src/lib/creator/mediaVault.ts` (read with `useMediaUrl`); saved state stores only name/size/type plus a small preview, file rules live in `src/lib/creator/mediaRules.ts`, deleting a library file clears lessons that pointed at it, and the shared editor lives in `products/CourseFields.tsx` (create step 5 and the Presentation tab). Why: videos are far too large for local storage, and older courses still load.
- Deleting a product moves it to a per-type Bin (`binnedAt`/`binnedFrom` on the item, status archived; rules in `src/lib/creator/bin.ts`, UI in `products/Bin.tsx`); Restore returns its old status, and Delete for good is blocked once anyone has bought it. Why: published products can be removed safely without breaking buyer access or sales history.
- New courses and unfinished course drafts (items with `builder`) use the three-step `products/CourseBuilder.tsx` (Basic information → More information incl. uploads → Pricing, then a full preview); rules live in `src/lib/creator/courseBuilder.ts`, answers save on `item.builder` and are mirrored into `course` config so older screens still read modules and lessons. Prices are never converted between currencies and Pay-As-You-Go suggested ranges are never inserted as prices. Why: creators set exact prices per currency and level, and pricing is always the last step.
