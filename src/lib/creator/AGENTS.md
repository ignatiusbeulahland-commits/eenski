- Public storefronts (`/store/$handle`, `components/storefront`) are read from creator dashboards saved on this device by `publicStore.ts` (live storefront + published items only); buying goes through the sitewide checkout and `creditStoreSales` records each sale (order, customer, activity) in that creator's saved state, keyed by payment reference so it never doubles. Why: creators can earn and withdraw in the prototype without inventing sales.
- Storefront page design lives on `/creator/storefront/customize`; its preview is a real `/store/$handle?preview=1` iframe fed unsaved changes through `draftKey` in localStorage (`applyDraft`, optional sample products from `sampleStore.ts`, never saved). `sample-creator` is the one page that opens in any browser. Photos/banners must be at least 1080 × 1080 and are cropped via `CropPicker` (`imageCrop.ts`); uploaded intro videos live in the media vault as `vault:<id>`. Page reports save to the admin store (`/admin/reports`). Why: a frontend-only prototype can't share one creator's saved page across browsers, so preview and sample data cover that honestly.
